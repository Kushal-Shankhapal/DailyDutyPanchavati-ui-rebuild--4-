### 3\. What the 11/09 Chart Extra Page Proves: Logical Sections vs. Physical PDF Page Count

The presence of an extra physical page on 11/09 (11.pdf Page 3 & Page 4 / 11.md Table 3 & Table 4\) proves an architectural principle regarding police station duty rosters:  
┌─────────────────────────────────────────────────────────────────────────┐  
│              LOGICAL SECTION VS. PHYSICAL PAGE SEPARATION               │  
├─────────────────────────────────────────────────────────────────────────┤  
│ CANONICAL LOGICAL DOMAIN SECTIONS (Fixed Structural Intent):             │  
│   \- Section 1: Day Shift Core ( दिवसपाळी तक्ता )                         │  
│   \- Section 2: Night Shift Core ( रात्रपाळी तक्ता )                       │  
│   \- Section 3: Leave, Special & External Duties ( इतर ड्युटी/रजा तक्ता )   │  
│   \- Section 4: Manpower Strength Matrix & Audit Log ( मनुष्यबळ तक्ता )   │  
│   \- Section 5: Supervisory Officer Summary ( पोलीस अधिकारी कर्तव्य )     │  
│   \- Section 6: Safe Nashik Scan Schedule ( सुरक्षित ॲप वेळापत्रक )        │  
├─────────────────────────────────────────────────────────────────────────┤  
│ DYNAMIC PHYSICAL PRINT PROJECTION (Fluid Paper Layout):                 │  
│   \- Standard Day: Logical Section 3 fits entirely on Physical Page 3\.   │  
│   \- Special Event Day (11/09): Ganeshotsav Equipment Table occupies     │  
│     Physical Page 3; Logical Section 3 flows onto Physical Page 4\.      │  
└─────────────────────────────────────────────────────────────────────────┘

* **Logical Sections Are Canonical; Physical Pages Are Fluid Output Projections**:  
* The Leave, Special & External Duties block is a **logical section** of the daily operational chart. In standard 6-page daily charts (10/09 and 16/09), Logical Section 3 fits on physical A4 Page 3\.  
* On 11/09, when a full-page equipment and dress rehearsal directive (रंगित तालीम) was added for Ganeshotsav preparation, physical Page 3 was absorbed by the equipment table (11.pdf Page 3), pushing Logical Section 3 onto physical Page 4 (11.pdf Page 4).  
* **Software & Database Architectural Invariant**:  
* The database schema must **never hardcode PDF cell coordinates or assume a static 1:1 mapping between logical domain sections and physical page numbers**.  
* The system must model operational entities (daily\_availabilities, special\_events, daily\_assignments) in a normalized schema. The document renderer dynamically compiles these entities into paged A4 layouts, allowing physical page counts to adapt naturally when special directives expand the document.
